# 14. 전체 개선 토론 기록 (2026-11-18)

팀장 요청: 쓸 수 있는 웹 개발·디자인 스킬을 모두 써서, 각 분야 전문가와 실제 사용자의 토론으로 결론을 내고 웹 전체를 다듬는다.

## 쓴 도구
- 요청한 `vercel-react-best-practices`, `webapp-testing`, `theme-factory`는 이 환경에 설치되어 있지 않고 스킬 목록에서도 찾을 수 없었다. 같은 일을 아래로 대신했다.
  - React 성능 점검 → 직접 점검(같은 자료를 여러 번 받는 문제, 이미지 불러오기)
  - 웹앱 테스트 → `tests/ui_smoke.js` 자동 화면 점검을 새로 만들어 휴대폰·PC에서 돌림
  - 테마 → 기존 `DESIGN.md` 위에 아이콘·태블릿·그래프 규칙을 더함
- 쓴 스킬: `website-design:web-review`(전체 점검), `dataviz`(그래프), `frontend-design`(구현), 앞서 쓴 `design:accessibility-review`·`design-critique`·`ux-copy`·`web-design-system`.

## 토론에 참여한 사람(역할)
| 구분 | 역할 |
|---|---|
| 전문가 | 접근성 전문가 · UX 디자이너 · 시각(브랜드) 디자이너 · 프런트엔드 성능 개발자 · 동해시 관광 기획자 |
| 사용자 | 휠체어 이용자(30대) · 무릎이 불편한 70대 어머니를 모시는 딸(보호자) · 유모차를 끄는 부모 · 외국인 여행자 |

## 점검에서 나온 것 (375 · 768 · 1280/1440px, 밝은·어두운 화면, 키보드)
1. 이모지 40여 개(☎ 🅿 🔋 🌧 🍽 🚕 …)가 아래 탭의 선 아이콘과 섞여 있음. 기기마다 모양·색이 다름
2. 태블릿(768px)에서 머리글이 두 줄로 꺾임 (위 메뉴는 보이는데 버튼이 밀림)
3. 같은 자료를 화면 조각마다 다시 받음: 장소 목록 5번, 붐빔 예측 3번, 날씨 2번
4. 사이트 아이콘·공유 미리보기(카카오톡 등)·주소창 색 없음
5. 첫 화면 '사진 멈추기'가 키보드 순서에서 입력칸보다 먼저
6. 붐빔 그래프가 빨강·노랑·초록 색만으로 정도를 알림, 방문자 그래프는 '보통' 노랑을 막대 색으로 씀, 표로 볼 방법 없음
7. (자동 점검으로 찾음) PC 위 메뉴 링크 42px, 줄 안 전화번호 링크가 작음

## 토론과 결론
**1. 이모지 → 공통 선 아이콘**
- 시각 디자이너: 한 화면에 이모지(색 그림)와 선 아이콘이 섞이면 '만들다 만' 느낌. 브랜드 색(바다 파랑)으로 통일해야 한다.
- 외국인 여행자: 🅿·🔋 같은 건 휴대폰마다 다르게 보여 헷갈렸다.
- 보호자(딸): 아이콘보다 옆 글자를 읽는다. 아이콘을 바꿔도 글자는 꼭 같이.
- 접근성 전문가: 아이콘은 꾸밈(aria-hidden), 뜻은 늘 글자로. 색만으로 뜻을 전하지 않기.
- **결론**: `components/Icon.tsx` 한 벌(2px 선, 글자색 따라감)로 날씨·브리핑·시간표·교통·빠른 메뉴까지 바꾼다. 아이콘 옆에는 늘 글자.

**2. 태블릿 머리글**
- UX 디자이너: 768~960px는 위 메뉴를 다 넣기 좁다. 휴대폰처럼 아래 탭이 손에 닿기도 쉽다.
- 휠체어 이용자: 태블릿을 휠체어 거치대에 두고 쓰면 아래쪽 버튼이 더 편하다.
- **결론**: 960px 이하에서는 위 메뉴 대신 아래 탭.

**3. 같은 자료 여러 번 받기**
- 성능 개발자: 무료 서버(Render Free)라 첫 접속이 느린데 같은 요청을 5번 보내면 더 느리다. 한 번 받아 나눠 쓰면 된다.
- 관광 기획자: 현장(바닷가)은 휴대폰 신호가 약한 곳이 많다.
- **결론**: `lib/api.ts`의 `getJSON`으로 한 번만 받고 같이 쓴다(실패하면 다음에 다시 받음).

**4. 공유 미리보기·사이트 아이콘**
- 보호자(딸): 일정을 가족 단톡방에 보내는데 링크에 그림이 안 떠서 스팸 같았다.
- **결론**: 동이 아이콘, 촛대바위 사진 미리보기, 주소창 남색.

**5. 키보드 순서**
- 접근성 전문가: 첫 화면에서 가장 먼저 닿아야 할 것은 입력칸이다.
- **결론**: '사진 멈추기'를 첫 화면 내용 뒤로.

**6. 그래프**
- 접근성 전문가·dataviz 규칙: 상태색(빨강·노랑·초록)만으로 정도를 알리면 색을 못 구분하는 사람은 모른다. 크기는 한 가지 색으로.
- 무릎이 불편한 어머니(보호자 통해): 숫자보다 "언제 가면 한산한지"만 알면 된다.
- **결론**: 막대는 바다 파랑 하나, 가장 한산한 3일만 주황 + '한산' 글자, 아래 '표로 보기'.

**7. 터치 크기**
- 휠체어 이용자: 손이 떨릴 때 작은 전화번호를 누르기 어렵다.
- **결론**: 위 메뉴·전화번호 링크도 44px.

**다루었지만 바꾸지 않은 것**
- 첫 화면 순서: 관광 기획자는 '권역으로 둘러보기'를 위로 올리자고 했지만, 대회 방향(선택과 집중: 코스 짜기가 먼저)을 지키기로 했다.
- 오른쪽 빠른 메뉴(넓은 PC에서만): 위 메뉴와 겹치지만 기능 삭제 금지 원칙에 따라 아이콘만 통일했다.

## 따로 다룰 것 (화면 작업 밖)
- '유모차로 비 오는 날' 예시 코스에서 실내 장소가 하나도 안 들어간 날이 있음 → 엔진(`engine.py`·`api.js`)의 비 오는 날 규칙 확인 필요 (둘 다 고치고 parity 확인).
- 관리자 화면에서 장소를 고친 뒤 같은 탭의 공개 화면은 새로고침해야 바뀐 값이 보임(`getJSON` 캐시).
