# 17. AI 중심 기능 3가지 — 전문가 회의 · 설계 · 작업 계획 (2026-11-20)

참석(관점): 접근성 전문가(휠체어 사용자 당사자), 고령자 UX 연구자, 동해시 관광 담당, AI 엔지니어(Claude API), 개인정보·운영 담당
팀장 요청: ① AI 코스 설계 에이전트 ② AI 접근성 판정관 ③ 최근 길 상태 요약 + 관리자 승인. 처리는 규칙 엔진이 아니라 **AI가 주도**. Haiku만 쓰던 것을 Sonnet도 쓸 수 있게.

## 1. 회의 결론

### 공통
- **AI가 판단의 주체**: 코스에 넣을 장소와 순서, 갈 수 있는지 판정, 제보 정리를 AI(Claude)가 근거를 읽고 결정한다. 규칙 엔진은 ① AI가 고른 코스의 도착 시각·영업시간 계산(검산 도구) ② AI가 실패했을 때 예비로만 쓴다.
- **근거와 확신도**(접근성 전문가 조건): AI 판정에는 반드시 근거(어느 자료의 어떤 내용)와 확신도(높음·보통·낮음)를 붙인다. 근거가 없거나 오래됐거나 서로 다르면 확신도를 낮추고 '직접 확인'을 권한다. 정보가 없으면 '판단 어려움(U)'.
- **데이터는 사람이 승인**(관광 담당 조건): AI는 제안만 하고, 사이트 데이터(알림·운영시간·편의시설)는 관리자가 [승인]을 눌러야 바뀐다.
- **개인정보**: 제보 사진은 이미 위치 정보(EXIF)를 지워 저장. AI에 닉네임·연락처를 보내지 않는다.
- **멈추지 않는 시연**: 키가 없거나 AI가 실패·거절하면 지금의 규칙 결과로 이어 간다. 화면에 'AI' / '규칙' 중 무엇으로 나온 결과인지 표시.

### 모델 (AI 엔지니어)
| 작업 | 기본 모델 | 이유 |
|---|---|---|
| AI 코스 설계 에이전트 | **Sonnet 5.5** (effort medium) | 여러 번 도구를 쓰며 계획하는 일이라 판단력이 중요 |
| AI 접근성 판정관 | **Sonnet 5.5** (effort medium) | 안전과 직결, 근거 비교 |
| 최근 길 상태 요약 | Haiku 5.5 (effort low) | 짧은 정리 작업, 양이 많음 |
| 대화형 동이·브리핑·사진 분석 등 기존 | Haiku 5.5 | 빠른 응답 |
- 비용: Sonnet 5.5는 1M 토큰당 입력 $2·출력 $10, Haiku 5.5는 $0.10·$0.50 (약 20배). 코스 설계 한 번 ≈ 입력 3만·출력 3천 토큰 → Sonnet 약 $0.09(약 130원), Haiku 약 $0.005. 판정 한 번 ≈ Sonnet 약 $0.01(약 15원). 시스템 프롬프트·도구 설명은 프롬프트 캐시로 재사용해 줄인다.
- 관리자 화면 [AI 설정]에서 작업마다 Haiku/Sonnet을 바꿀 수 있다(총괄 관리자). 환경 변수 `AI_MODEL_FAST`, `AI_MODEL_SMART`로 모델 이름도 바꿀 수 있다.
- Sonnet 5.5는 안전 분류기가 드물게 거절할 수 있어 공식 권장대로 서버 측 대체(`fallbacks: "default"`)를 켠다. Haiku는 대체 기능이 없어 거절 시 규칙 결과로.
- 구현은 공식 Python SDK(`anthropic` 2.x)로 하나의 모듈(`backend/app/ai.py`)에 모은다. 기존 HTTP 직접 호출(llm.py, talk.py)도 이 모듈로 옮긴다.

### ① AI 코스 설계 에이전트 (고령자 UX·관광 담당)
- 동이 대화든 버튼 질문이든 '코스 만들기'는 AI 에이전트가 맡는다. 에이전트는 도구로 장소를 찾아보고(`find_places`), 자세히 보고(`place_detail`), 짠 순서를 검산(`check_plan`: 도착 시각·영업시간·휴무·이동 시간)한 뒤 최종 코스를 JSON으로 낸다.
- 지킬 것: 꼭 갈 곳(담은 곳)·뺄 곳, 이동 조건에 '어려움(R)'인 곳 금지, 이동 조건이 있으면 접근성 확인된 곳만, 점심은 11:20~14:00 사이 식당, 이동이 불편하면 쉬는 카페, 하루 4곳 안팎, 비 오면 실내. 장소마다 '왜 골랐는지' 한 문장.
- 사용자는 기다리는 동안 "AI가 장소를 찾아보고 코스를 짜는 중"을 본다(최대 약 30초). 실패하면 규칙 코스로.
- 고치기(빼기·바꾸기 등 빠른 수정)는 지금처럼 즉시 처리(규칙). '다른 곳으로 새로 짜기'·위쪽 새 입력·여러 날은 AI.

### ② AI 접근성 판정관 (접근성 전문가)
- 관광지 상세의 '이동 및 접근성' 맨 위에 'AI 판정' 카드: 누구 기준(휠체어·유모차·오래 걷기 어려움)에 따라 가능/주의/어려움/판단 어려움, 확신도, 한 줄 결론, 근거(출처 표시), 주의할 점, 가기 전에 전화로 물어볼 것.
- 근거 자료: 구간 정보(출처·확인일), 한국관광공사 무장애 정보, 편의시설, 보호자 꿀팁, 최근 90일 제보·길 메모, 진행 중인 임시 알림.
- 같은 근거·같은 기준이면 1시간 동안 저장해 다시 묻지 않는다.

### ③ 최근 길 상태 요약 + 관리자 승인 (관광 담당·운영)
- 재료: 현장 제보(사진 + AI 사진 분석)와 이제부터 서버에도 저장되는 장소 '한 줄 후기·길 메모'(커뮤니티). 최근 90일, 반려된 제보 제외.
- AI가 장소마다: 상태(문제 없음/주의/문제 있음), 한 줄 요약, 항목(공사·고장·막힘·칭찬·정보, 날짜, 건수), **데이터 수정 제안**(임시 알림 / 운영시간 / 편의시설 추가·삭제)과 근거 제보 번호.
- 공개 화면: 관광지 상세에 '최근 길 상태 (AI 요약)'. 제보가 없으면 보이지 않음.
- 관리자 [AI 제안] 탭: 제안 목록(근거 제보 원문 함께) → [승인]이면 사이트 데이터에 바로 반영(이력에 'AI 제안 승인'으로 남고 되돌리기 가능), [반려]면 닫힘. [제보 있는 장소 다시 정리] 버튼.

## 2. 작업 계획 (이 순서로, 단계마다 검증)
1. `ai.py`: SDK 클라이언트, 작업별 모델 고르기(환경 변수 → 관리자 설정), Sonnet 서버 측 대체, 구조화 출력(JSON 스키마) 도우미, 도구 반복 도우미, 사용량 집계, 거절·토큰 초과 처리. → 가짜 클라이언트로 단위 시험.
2. 기존 `llm._ask_json`, `talk._llm`을 `ai.py`로 옮김. → 대화 평가(규칙)·관리자 점검·서버/데모 비교가 그대로인지.
3. `ai_judge.py` + `GET /api/ai/judge/{pid}` + 상세 화면 카드. → 가짜 응답 시험(근거 없으면 U, 잘못된 값 거름, 캐시).
4. `ai_course.py`(도구 3개 + 고정 순서 시간 계산) + `/api/course`·대화의 코스 만들기 연결. → 가짜 에이전트 시험(도구 호출 → 검산 → 최종 JSON → 코스), 잘못된 id·숙박·빼기 목록 무시, 실패 시 규칙.
5. `ai_status.py` + 길 메모 서버 저장 + 상세 카드 + 관리자 [AI 제안]·[AI 설정]. → 승인하면 알림이 생기고 되돌리기 되는지.
6. 전체 검사(타입·빌드·서버/데모 비교·대화 평가·관리자 점검·새 시험) → 배포 → 실제 키로 세 기능 확인.

## 3. 프롬프트 원칙 (세 기능 공통)
- 역할과 목표를 먼저, 지킬 규칙은 번호 목록으로 짧게. 근거에 없는 사실(경사도·운영시간·전화번호)을 지어내지 않는다.
- 출력은 JSON 스키마로 강제(구조화 출력)하고 서버가 다시 검증(허용된 값·장소 id·길이).
- 쉬운 한국어 존댓말, 영어 화면이면 영어.
