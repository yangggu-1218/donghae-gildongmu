로컬 서버(`localhost:8765`)를 PC(1280px)·휴대폰(375px)으로 띄워 첫 화면, 코스 결과, 관광지, 장소 상세, 숙소를 봤다.
도구: Design 플러그인 `accessibility-review`(WCAG 2.1 AA) · `design-critique` · `ux-copy`, 브라우저 안 자동 측정(버튼 크기·글자 크기·대비).

## 2. 디자인 비평

첫인상: 실제 촛대바위 사진과 큰 질문 한 줄이 서비스 목적을 바로 말한다. 다만 휴대폰에서는 첫 화면 전체가 사진+예시 문장 4개라 '코스 짜기' 대화가 두 화면 아래에 있다.

| 찾은 점 | 정도 | 고칠 방법 |
|---|---|---|
| **숫자 띠(10곳·79곳…)가 '지금의 동해' 카드를 덮음** — 원래 사진 바로 아래 겹치려고 넣은 위로 당김(-48px)이 순서를 바꾼 뒤에도 남음 | 🔴 | 위로 당김 없앰 |
| 관광지 화면: 이 서비스의 핵심인 '누구 기준으로 볼까요?(휠체어·유모차)'가 관심사 칩 9개·권역 탭 아래 맨 끝에 있어 휴대폰에선 안 보임 | 🟡 | 검색 바로 아래로 올림 |
| 장소 상세(휴대폰): 사진이 한 화면을 다 차지하고 '갈 수 있는지(구간 판정)'는 한참 아래 | 🟡 | 휴대폰 사진 높이 줄임(16:9) |
| 장소 상세: '상시 개방 상시 개방'처럼 같은 말이 두 번 | 🟢 | 같으면 한 번만 |
| 첫 화면(휴대폰): 예시 문장 4개가 세로로 쌓여 길다, 위 여백 120px | 🟡 | 휴대폰은 한 줄 가로 스크롤, 위 여백 줄임 |
| 동이 말풍선이 모두 진한 2px 파랑 테두리라 무겁고 '틀에 찍은' 느낌 | 🟢 | 옅은 바다빛 바탕 + 얇은 테두리 |
| CSS가 덧댄 규칙으로 쌓여 같은 것(.toast, .qc, .when, .dchip)을 두세 번 정의 | 🟢 | 겹친 규칙 정리 |

잘 된 점: 대화 칸(위 진행 단계 · 가운데 대화 · 아래 답 버튼)이 한 화면에 들어옴, 시간표+지도+브리핑이 한눈에, 예시 판정을 숨기지 않는 정직한 표시, 실제 사진.

## 3. 문구 (ux-copy)

| 지금 | 바꿀 말 | 이유 |
|---|---|---|
| 메뉴 '코스 만들기' / 버튼 '코스 짜기' / 제목 '동이와 코스 짜기' 섞임 | 모두 **코스 짜기** | 같은 일에 같은 말 |
| 판정 '가능 · 주의 · 불가' (첫 화면은 '어려워요') | **가능 · 주의 · 어려움** | '불가'는 딱딱하고 첫 화면과 다름 |
| 시간표 '이 코스 빼기' | **이곳 빼기** | 빼는 건 코스가 아니라 장소 |
| '다른 곳으로 교체' | **다른 곳으로 바꾸기** | 쉬운 말 |
| '오르막 코스 빼기' · '실내 코스로 변경' | **오르막 있는 곳 빼기** · **실내 위주로 바꾸기** | 같은 이유 |
| 머리글 '안심' | **긴급·도움** | 눌러야 무엇이 나오는지(119·안내소·충전기) 알게 |
| '길을 비춰 보는 중이에요.' | **갈 수 있는 길인지 확인하는 중이에요…** | 무엇을 기다리는지 분명히 |
| '서버와 연결되지 않아요. 잠시 뒤 다시 해 주세요.' | **…처음 접속은 30초쯤 걸릴 수 있어요. 잠시 뒤 다시 눌러 주세요.** | 무료 서버라 첫 접속이 느림 |
