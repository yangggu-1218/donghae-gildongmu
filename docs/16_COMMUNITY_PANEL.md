# 16. 커뮤니티 · 내 장소·숙소 추가 — 전문가 회의 정리 (2026-11-19)

참석(관점): 접근성 전문가(휠체어 사용자 당사자 관점), 고령자 UX 연구자, 동해시 관광 담당 공무원, 서비스 디자이너, 개인정보·운영 담당

## 1. 커뮤니티 — 결론
- **이름**: '다녀온 길' (여행 후기 게시판보다 '길 정보를 나누는 곳'이라는 성격을 드러냄). 메뉴에는 '커뮤니티'로 표시해 바로 알아보게.
- **가치의 중심은 별점이 아니라 '길 정보'**: 글마다 "입구 턱 있었어요", "엘리베이터 고장" 같은 **길 메모**를 따로 받는다. 접근성 전문가: 공식 데이터보다 다녀온 사람의 최근 메모를 더 믿는다. 관광 담당: 이 메모가 쌓이면 관리자 제보 검수와 이어질 수 있다.
- **글 = 코스**: 글마다 다녀온 장소 순서를 '코스 띠'(작은 노선도)로 보여 주고 [이 코스로 짜 보기]를 누르면 그 장소들을 '꼭 갈 곳'에 담아 코스 짜기로 이동. 읽는 것에서 바로 쓰는 것으로.
- **골라 보기**: 무장애/일반, 이동 조건(휠체어·유모차·어르신), 권역, 정렬(최신·추천 많은 순). 고령자 UX: 고르는 버튼은 크게, 한 줄에 너무 많이 두지 않기.
- **반응**: '도움 됐어요'(추천) 하나만. 좋아요·싫어요·북마크를 따로 두지 않는다(단순하게). 댓글은 글 상세에서.
- **관광지 상세**: '다녀온 사람들 이야기' — 그 장소가 들어간 글과 장소 한 줄 후기·길 메모를 보여 주고 남길 수 있게.
- **개인정보·운영**: 로그인 없이 닉네임만. 사진·연락처는 받지 않음. 글·댓글에 [신고] 버튼(지금은 이 기기에서 가림). 대회 시연판은 **이 브라우저에만 저장**(서버 저장은 관리자 검수 기능과 함께 다음 단계).
- **예시 글 20개**: 비어 보이지 않게 넣되, 목록 위에 '시연용 예시 글'이라고 작게 밝힌다(심사·실사용자 오해 방지). 닉네임은 실존 인물이 아닌 생활형 닉네임.

## 2. 코스 뒤 '내 장소·숙소 추가' — 결론
- **장소 추가**: 코스 결과에 [장소 더 넣기] → 검색(오타 허용)으로 고르면 기존 '넣어 줘' 수정 기능(add)을 그대로 씀 → 영업시간·순서까지 다시 맞춰 줌. 엔진 규칙을 새로 만들지 않아 서버·데모 결과가 그대로 같다.
- **숙소 추가**: [내 숙소 넣기] → 동해시 숙박 공공데이터 173곳에서 검색해 고름. 숙소는 코스의 **마지막 도착지**로 지도·카카오 길찾기에 붙고 '마지막 장소에서 차로 약 n분'을 보여 줌. 공공데이터에 좌표가 없어 카카오 주소 검색으로 위치를 찾는다(못 찾으면 그렇게 알려 줌).
- 디자이너: 버튼은 지도 위 한 줄에만. 코스 카드 사이에 넣지 않는다(난잡함 방지).

## 3. 디자인 메모 (frontend-design 스킬 기준)
- 이 사이트의 색·글꼴(--sea 파랑, --sun 주황, Jua 제목)을 그대로 쓰고, 커뮤니티만의 한 가지 특징은 **코스 띠**(장소를 점과 선으로 잇는 작은 노선도)로 둔다. 나머지는 조용하게.
- 카드는 정보 순서: 제목 → 코스 띠 → 길 메모 한 줄 → 작성자·날짜·도움 됐어요·댓글 수.
- 버튼 문구는 하는 일 그대로: [이 코스로 짜 보기], [글 올리기], [댓글 남기기], [도움 됐어요].

## 4. 2차 회의 (2026-11-19 저녁) — 편의시설 지도·커뮤니티 문의·아래쪽·로그인
- **사용자와 정한 것**: 로그인은 '이 기기 로그인'(서버 무료 등급이라 서버 계정은 재시작 때 사라짐), 문의는 관리자 화면 [문의] 탭에 모음
- **편의시설 지도**(접근성·관광 담당): 층 순서를 숙소 → 약국·병원 → 공영주차장 → 관광안내소 → 장애인 화장실 → 충전기로. 약국·병원은 긴급·도움과 같은 국립중앙의료원 실데이터를 씀(서버에 키가 없으면 예시라고 표시). 숙소 158곳은 주소를 카카오 주소 검색으로 한 번 좌표로 바꿔 데이터로 저장(매번 검색하지 않음). 점이나 목록을 누르면 반경 약 500m(지도 레벨 4)로 확대
- **커뮤니티**(서비스 디자인): 첫 화면에서 '이야기 나누기'와 '문의하기' 두 문으로 나누고, 모든 하위 화면에 [커뮤니티로 돌아가기]. 문의 화면은 자주 묻는 질문 → (접어 둔) 여행 준비물 → 급할 때 → 내 문의 → 문의하기 순. 답을 먼저 찾게 해 문의 수를 줄이는 공공 누리집의 일반적인 흐름
- **아래쪽**(한국관광공사 누리집 아래쪽 참고): 관리자는 작은 상자로 왼쪽 끝, 동해시·한림대 로고(같은 높이, 누르면 공식 누리집), 오른쪽은 동해시 누리집에 실린 공식 SNS(페이스북·카카오톡 채널·인스타그램·유튜브·블로그). X·밴드는 공식 계정을 찾지 못해 넣지 않음. 출처·판정 기준은 관리자 화면 탭으로
- **프로필**(고령자 UX): 관광 누리집 마이페이지처럼 프로필 카드 → 활동 숫자(내 일정·담은 장소·내 글·내 문의) → 탭 → 여행 설정(이동 조건·좋아하는 여행). 이메일·전화번호는 받지 않음

## 5. 3차 회의 (2026-11-20) — 관광지 목록 화면
참석(관점): 접근성 전문가, 고령자 UX 연구자, 서비스 디자이너, 동해시 관광 담당 / 참고: 팀장 시안, 한국관광공사 열린관광 '무장애 검색'
- **무장애 검색 띠**(접근성): 처음엔 접힌 띠 하나. 열면 지체장애·시각장애·청각장애·영유아 가족·고령자 상자 5개 → 상자를 고르면 그 분류의 세부 항목(열린관광 항목 이름 그대로: 주차여부·주 출입 접근로·휠체어대여·엘리베이터·화장실 등)이 체크 상자로. 열린관광과 같은 말을 써서 두 사이트를 오가도 헷갈리지 않게. 청각장애는 동해 관광지에 등록된 정보가 아직 없어 그렇다고 밝힘(빈 결과로 두지 않음)
- **'누구 기준' 판정은 유지**: 지체장애 → 휠체어, 영유아 가족 → 유모차, 고령자 → 오래 걷기 어려움 기준으로 카드에 신호등과 정렬. 상자만 고르면 장소를 숨기지 않고 판정만 보이고, 세부 항목을 체크해야 거른다(정보가 없는 곳을 '안 된다'로 오해하지 않게)
- **맞춤 필터·정렬은 눌러서 여는 상자**(서비스 디자인): 첫 화면의 칩 줄을 없애 화면을 단순하게. 고른 조건은 도구 막대 아래 작은 칩으로 남겨 무엇이 켜졌는지 늘 보이게, 하나씩·모두 풀기
- **지역 탭(전체 + 5권역) 유지**(관광 담당): 동해시가 홍보하는 권역 구분과 같음
- **카드**(고령자 UX): 사진 → 분류 태그 → 이름 → 한 줄 소개 → 편의 아이콘(휠체어·장애인 주차·장애인 화장실·유모차) → [코스에 담기] [자세히 보기]. 하트만으로는 뜻이 안 읽혀 글자 버튼 유지. 카드 어디를 눌러도 상세로. 한 쪽 12곳, 쪽 번호
