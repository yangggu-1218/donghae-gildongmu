# 19. 시(市)를 위한 기능 — 불편 제보를 AI가 정리해 시 담당자에게 (2026-11-21)

동해 길동무를 **투트랙**으로 운영한다.
- 트랙 1 (이용자): 무장애 여행 코스 추천 — 지금까지 만든 것
- 트랙 2 (동해시): 이용자가 알린 '다니기 불편한 곳'을 AI가 정리·분류해 시 담당자에게 넘기고, 처리 결과를 다시 이용자와 여행 정보에 돌려준다

참석(관점): 동해시 민원·도로 관리 담당 공무원, 장애인 접근성 전문가(휠체어 이용 당사자), UX 디자이너, AI·백엔드 개발자, 개인정보 보호 담당자
팀장 조건: 새로 따로 만들지 말고 이미 있는 **현장 제보·길 메모·최근 길 상태 요약·[AI 제안] 승인 흐름**을 이어서 쓴다. 이미 넣은 AI 요청 수 제한·하루 비용 상한 안에서 돈다.

## 1. 회의 기록 (요약)

**민원·도로 담당 공무원**
- "민원은 '어디'가 제일 중요하다. 관광지 이름이 아니라 **좌표와 사진**이 있어야 현장에 나간다. 보도·횡단보도 턱은 관광지 밖에 더 많다."
- "같은 곳 민원이 10건 오면 10번 처리하지 않는다. **묶어서 한 건**으로 보고, 몇 명이 알렸는지가 우선순위 근거가 된다."
- "담당 부서가 다르다: 보도·턱은 도로 담당, 불법 주차는 교통 담당, 관광지 안 시설은 관광 담당, 공중화장실은 화장실 관리 담당. 부서 이름은 시마다 달라서 **관리자가 고칠 수 있는 목록**이어야 한다."
- "처리 상태는 **접수 → 확인 → 처리 중 → 완료** 네 단계면 충분하다. 반려(시 소관 아님·사유 기재)와 중복도 있어야 한다."
- "주간·월간으로 '몇 건 들어와서 몇 건 처리했는지, 어디가 많은지'를 **한 장 보고서**로 받고 싶다. 결재에 붙일 수 있게 인쇄·내려받기."
- "7일 넘게 '접수'에 머문 건은 눈에 띄게 해 달라."

**접근성 전문가 (휠체어 이용 당사자)**
- "불편의 종류를 고르게 하되, **'누가' 불편한지**(휠체어·유모차·보행 약자·시각)를 같이 받아야 심각도가 나온다. 2cm 턱은 걷는 사람에겐 아무것도 아니지만 수동 휠체어엔 벽이다."
- "심각도는 **'지나갈 수 없음 / 도움이 있어야 지나감 / 불편함'** 세 단계로. 숫자 점수보다 이 말이 현장과 맞는다."
- "제보한 사람이 **결과를 들을 수 있어야** 다시 알린다. 완료되면 '고쳐졌어요' 알림과 가능하면 고친 뒤 사진."
- "고쳐지기 전까지는 **여행 정보에 바로 반영**(임시 알림·우회 안내)돼야 당사자가 헛걸음하지 않는다 — 이미 있는 [AI 제안] 승인 흐름에 붙이자."

**UX 디자이너**
- "입력은 **3단계, 1분 안에**: ① 어디(내 위치 / 지도에서 콕 / 관광지 고르기) ② 무엇(그림 단추 8개 + 누가 불편) ③ 사진·한마디(둘 다 선택). 글쓰기를 강요하지 않는다."
- "사진만 찍어도 되게. 사진이 있으면 AI가 종류를 **미리 골라 두고** 이용자는 '맞아요'만 누르게."
- "들어가는 곳은 여러 군데지만 **폼은 하나**: 머리말 [불편 알리기], 관광지 상세, 편의시설 지도, 코스 결과 화면, 동이 대화('여기 턱이 높아요' → 폼을 채워서 열기), 음성 입력(기존 마이크 단추)."
- "보내면 **접수번호**(예: DH-4821)와 '같은 곳에 n명이 이미 알렸어요'를 보여 준다. [내 제보]에서 단계 막대로 상태 확인."
- "위험·사고는 이 폼이 아니라 **119 / 동해시 민원 전화**로 — 폼 맨 위에 한 줄."

**AI·백엔드 개발자**
- "사진 분석과 분류를 **한 번의 Haiku 호출**로(사진 + 글 + 선택지 → 장애물 종류·심각도·분류·부서·한 줄 요약). 제보 한 건 약 0.05원 수준."
- "비슷한 제보 묶기는 AI 없이 **규칙**으로 먼저: 같은 종류 + 30m 안 + 60일 안. 묶음 요약 문장만 AI(Haiku). 비용이 제보 수에 비례해 늘지 않게."
- "기간 보고서는 하루 한두 번 담당자가 누를 때만 → 여러 묶음을 비교·판단하는 일이라 **Sonnet**. 나머지는 모두 Haiku. [AI 설정]에서 바꿀 수 있다."
- "AI 답은 서버가 다시 검사: 정해진 종류·부서·심각도 값만, 근거 없는 '지나갈 수 없음'은 낮추기, 요약에 개인정보 패턴(전화·차량번호) 있으면 지우기."
- "AI가 실패·한도 초과면 **규칙 분류**: 이용자가 고른 종류 → 부서 표, 선택한 '누가 불편' + 종류로 심각도 표. 화면에 'AI'/'규칙' 표시."
- "저장은 지금 `reports.jsonl` 하나를 **그대로 확장**(새 칸 추가, 예전 기록도 읽힘). 저장소를 바꿀 수 있게 읽기·쓰기를 `reports_store.py` 한 곳으로 모은다."

**개인정보 보호 담당자**
- "**회원가입 없이** 제보. 닉네임·연락처는 받지 않는 게 기본. 답을 받고 싶은 사람만 연락처(전화 또는 이메일)를 **동의와 함께** 받고, 완료 90일 뒤 자동 삭제."
- "사진 **EXIF는 이미 지운다**(다시 저장). 다만 촬영 위치를 쓰고 싶으면 '사진 찍은 위치 쓰기'에 체크한 경우에만 EXIF 좌표를 읽고 바로 버린다."
- "사진 속 **얼굴·차량 번호판**: AI가 보이는지 표시하고, 보이면 담당자 화면에 '개인정보 포함' 경고. **제보 사진은 일반 이용자에게 공개하지 않는다**(담당자만). 가리기(모자이크)는 2차로."
- "불법 주차 제보는 **번호판이 핵심 증거**라 시 담당자는 볼 수 있어야 하지만 AI 요약·공개 화면·보고서에는 번호를 쓰지 않는다."
- "AI에게는 닉네임·연락처·IP를 보내지 않는다. 공개 지도에는 **2명 이상 알린 묶음만**, 사진 없이, 종류와 상태만."
- "수집 항목·보관 기간을 폼 아래 한 줄로 알리고, 자세한 건 처리방침 페이지로."

## 2. 결정한 기능

### 2-1. 이용자 쪽
| 기능 | 내용 |
|---|---|
| 들어가는 곳 | 머리말 [불편 알리기](새) · 관광지 상세 · 편의시설 지도 · 코스 결과(기존 ReportBox를 이 폼으로) · 동이 대화(말하면 폼을 채워 열기) |
| ① 어디 | 내 위치 / 지도에서 콕 찍기 / 관광지 고르기(가까운 관광지는 자동 연결) / 사진 찍은 위치 쓰기(동의 체크) |
| ② 무엇 | 그림 단추 8개: 턱·계단 · 깨진 보도·바닥 · 경사로 없음·가파름 · 불법 주차·길 막힘 · 화장실 문제 · 엘리베이터·리프트 고장 · 공사·통제 · 기타 / 누가 불편: 휠체어·유모차·걷기 힘듦·시각 |
| ③ 사진·한마디 | 사진 최대 3장(선택), 한마디(선택, 마이크로 말해도 됨). 사진이 있으면 AI가 ②를 미리 골라 둠 |
| 받고 싶으면 연락처 | 선택 + 동의 체크. 없으면 접수번호로만 확인 |
| 보낸 뒤 | 접수번호 · AI가 본 내용 한 줄 · '같은 곳에 n명이 알렸어요' · 처리 단계 막대 |
| 내 제보 | [내 일정] 아래 '내가 알린 곳'(이 기기) + 접수번호로 찾기. 상태 4단계 + 시의 답변 + (있으면) 고친 뒤 사진 |
| 공개 지도 | 편의시설 지도에 '알려진 불편' 층(끄고 켜기): 2명 이상 묶음만, 종류·상태·건수, 사진 없음 |

### 2-2. AI 쪽 (모두 `backend/app/ai.py` 공통 모듈, 실패하면 규칙)
| 작업 | 모델 | 언제 | 하는 일 | 서버 검사 |
|---|---|---|---|---|
| 제보 정리(사진 분석+분류) `triage` | Haiku | 제보 1건마다 | 장애물 종류, 심각도(지나갈 수 없음/도움 필요/불편), 분류, 담당 부서·우선순위 제안, 한 줄 요약, 얼굴·번호판 보임 여부 | 정해진 값만, 사진·글 근거 없는 '지나갈 수 없음'은 '도움 필요'로, 요약 속 전화·차량번호 지우기 |
| 묶음 요약 `cluster` | Haiku | 묶음에 새 제보가 들어올 때(같은 내용이면 캐시) | 묶음 제목·상황 요약·여러 제보의 공통점 | 길이, 개인정보 패턴 |
| 기간 보고서 `report` | **Sonnet** | 담당자가 [보고서 만들기] 누를 때 | 기간 핵심 3줄, 많이 몰린 곳, 오래 밀린 건, 부서별 할 일, 다음 기간 제안 | 숫자는 서버가 계산해 넘기고 AI는 문장만(숫자를 지어내지 않게) |
| 여행 정보 반영 제안 | Haiku (기존 `status`) | 묶음이 '확인' 이상일 때 | 기존 [AI 제안]으로 임시 알림 제안 → 승인하면 관광지 상세·코스에 반영, 완료되면 알림 내리기 제안 | 기존 그대로 |

- 규칙 대신(AI 없음·실패·한도 초과): 이용자가 고른 종류 → 부서 표, '누가 불편'×종류 → 심각도 표, 우선순위 = 심각도 + 알린 사람 수 + 경과일.
- **AI가 낸 분류·심각도·부서·우선순위는 담당자가 고칠 수 있고**, 고친 값과 '누가 고쳤는지'가 남는다(AI 값은 따로 보관 → 나중에 정확도 확인).

### 2-3. 시 담당자 쪽 (관리자 [제보 검수] 탭을 **[제보·민원]**으로 키움 — 기존 기능 유지)
| 화면 | 내용 |
|---|---|
| 목록 | **묶음 단위**(펼치면 개별 제보). 열: 우선순위 · 종류 · 위치 · 알린 수 · 상태 · 부서 · 경과일(7일 넘게 '접수'면 빨강) · AI/규칙. 거르기: 상태·종류·부서·우선순위·기간·가상 포함 |
| 묶음 상세 | 사진(담당자만, 개인정보 경고), AI 분석, 분류·심각도·부서·우선순위 고치기, 상태 바꾸기 + 이용자에게 보일 답변, 묶음 합치기·떼기, 고친 뒤 사진 올리기, [여행 정보에 알리기] → 기존 임시 알림 |
| 몰리는 곳 지도 | 카카오맵에 묶음 점(크기 = 알린 수, 색 = 심각도), 숫자 묶음(기존 MarkerClusterer), 기간·종류 거르기 |
| 기간 요약 | 이번 주/이번 달/직접 기간: 들어온 수·처리 수·평균 처리일·종류별·부서별 막대, 많이 몰린 곳 5, 오래 밀린 건 + AI 요약(Sonnet). 인쇄·CSV 내려받기 |
| 설정 | 부서 목록·종류별 기본 부서(총괄 관리자), 가상 데이터 넣기/모두 지우기 |

**더 제안하는 것 (시 담당자에게 도움이 될 것)**
1. **개선 우선순위 점수**: 알린 사람 수 × 심각도 × **관광객 동선**(길동무 코스에 자주 들어가는 장소 근처인지) — 길동무만 가진 데이터라 예산 배정 근거로 쓸 수 있다.
2. **고친 전·후 사진**: 완료할 때 '고친 뒤' 사진 → 이용자 알림 + 시 홍보 자료.
3. **처리 기한(SLA) 표시**: 종류별 목표 일수(예: 불법 주차 1일, 턱 30일)를 넘으면 강조.
4. **외부 민원 시스템 이관**: CSV 내려받기(국민신문고·안전신문고·새올로 옮기기 쉽게 칸 맞춤). 직접 연동은 시와 협의 뒤.
5. **현장 확인 기록 연결**: 담당자·조사원이 [현장 확인 기록]을 남기면 그 묶음이 '확인'으로 넘어가고, 측정값이 장소 구간 정보 제안으로 이어짐(기존 흐름).

### 2-4. 이미 있는 것과 합치는 방법 (새로 따로 만들지 않음)
```
이용자 입력 ──┬─ 불편 알리기 폼(새, 기존 /api/reports 확장)
              ├─ 코스 결과 ReportBox(기존 → 같은 폼)
              └─ 커뮤니티 길 메모(기존 /api/place-notes)
                        │  모두 reports.jsonl 한 곳에 (source 칸으로 구분)
                        ▼
        AI 제보 정리(triage, Haiku) ─ 실패하면 규칙 ─▶ 묶음(규칙: 종류+30m+60일) ─▶ 묶음 요약(Haiku)
                        │                                        │
                        ▼                                        ▼
   [제보·민원] 목록·지도·기간 보고서(Sonnet)        ③ 최근 길 상태 요약(기존, 같은 제보 사용)
     담당자: 분류 고치기·상태·답변                    └▶ [AI 제안] 임시 알림 → 승인 → 관광지 상세·코스(기존)
                        │
                        ▼
        이용자 [내 제보] 상태·답변 / 공개 지도 '알려진 불편'
```
- 상태 이름 맞추기: 예전 '확인 중' → **확인**, '반영' → **완료**로 읽고, 새로 '처리 중' 추가. '반려'는 그대로(사유 필수), '중복'은 묶음에 합쳐질 때.
- 관광지 밖 제보(보도·횡단보도)는 `place_id` 없이 좌표만. 300m 안에 관광지가 있으면 그 장소에 연결해 '최근 길 상태'에도 쓰인다.

## 3. 개인정보

| 항목 | 다루는 방법 |
|---|---|
| 제보자 | 로그인 없음. 닉네임·연락처 받지 않음(기본). 답을 원하면 연락처 + 동의 → 완료 90일 뒤 자동 삭제. AI에 보내지 않음 |
| 사진 EXIF | 다시 저장하며 모두 지움(기존). '사진 찍은 위치 쓰기'에 체크했을 때만 좌표를 읽고 바로 버림 |
| 얼굴·번호판 | AI가 '보임' 표시 → 담당자 화면 경고. 사진은 담당자만 봄(공개 안 함). AI 요약·보고서·공개 지도에 번호 쓰지 않음(서버가 한 번 더 지움). 모자이크는 2차 |
| 위치 | 공개 지도는 2명 이상 묶음만, 묶음 중심점으로(개별 좌표 안 보임) |
| 보관 | 제보 글·분류는 계속(통계), 사진은 완료 1년 뒤 삭제(설정 가능), 연락처는 완료 90일 뒤 |
| 접근 기록 | 담당자가 상태·분류를 바꾸면 이력에 '누가·언제' (기존 이력) |
| 고지 | 폼 아래: "사진·위치·내용은 동해시 담당자가 처리에 써요. 사진은 공개하지 않아요. 연락처는 원할 때만, 처리 뒤 90일에 지워요." |

## 4. 비용 (이미 넣은 한도 안에서)
- 제보 1건 triage(Haiku, 사진 1장 ≈ 1,600토큰 + 글 ≈ 1,000토큰, 답 ≈ 400토큰) ≈ $0.0005 (약 0.7원). 하루 100건이어도 약 70원.
- 묶음 요약(Haiku) 새 제보가 들어온 묶음만 ≈ $0.0003.
- 기간 보고서(Sonnet, 묶음 50개 요약 ≈ 입력 8천·출력 1천 토큰) ≈ $0.026 (약 36원) — 담당자가 누를 때만, 같은 기간·같은 데이터면 하루 동안 캐시.
- 기존 `gate`(같은 주소 10분 20번, 하루 $2)를 그대로 지남. 여기에 **제보 보내기 자체**도 같은 주소 1시간 10건으로 제한(스팸 방지, AI와 별개).
- 한도에 걸리면 규칙 분류로 접수는 그대로 된다(제보가 막히지 않음).

## 5. 저장 문제 (Render Free = 디스크 없음) — 제안
제보는 **시의 행정 기록**이라 잃으면 안 된다. 세 단계로 제안한다.

| 단계 | 방법 | 비용 | 코드 |
|---|---|---|---|
| A. 지금 바로 (대회·시연) | 관리자 [제보·민원]에 **'백업 내려받기'**(제보 JSON + 사진 zip)와 **'백업 올리기'**, 저장소가 영구가 아니면 관리자 화면 맨 위에 경고 띠 | 0원 | 이번에 구현 |
| B. 시범 운영 (권장) | Render **Starter + 디스크 1GB** — `render.yaml`이 이미 이렇게 되어 있어 요금제만 바꾸면 됨(`/var/data`에 제보·사진·cms 저장) | 월 약 $7.25 | 바꿀 것 없음 |
| C. 정식 운영 | 시 서버 또는 관리형 DB(PostgreSQL) + 사진은 객체 저장소. `reports_store.py`만 바꾸면 되게 이번에 읽기·쓰기를 한 곳으로 모아 둠 | 시와 협의 | 2차 |

## 6. 가상 데이터 (3단계 점검용)
- `data/sample_reports/reports.jsonl` + 사진 없이(또는 그림) 18건, 모든 기록에 `"sample": true`, 화면에 **[가상]** 표시.
- 실제 저장 파일(`reports.jsonl`)과 **섞지 않는다**: 서버가 읽을 때만 합치고, 관리자 [설정]의 '가상 데이터 보기'를 켰을 때만 목록·지도·보고서에 나온다. **[가상 데이터 모두 지우기]** 한 번으로 정리.
- 몰리는 곳: 묵호항 앞 보도(턱·깨진 보도 5건), 동해역 앞 횡단보도(턱 3건), 추암 공영주차장(불법 주차 3건), 그 밖에 흩어진 7건.

## 7. 화면 흐름
**이용자**: [불편 알리기] → ① 어디 → ② 무엇·누가 → ③ 사진·한마디(선택) → 보내기 → 접수 화면(접수번호·AI 한 줄·같은 곳 n명) → [내 제보]에서 단계 확인
**시 담당자**: [제보·민원] → 목록 ⇄ 몰리는 곳 지도 ⇄ 기간 요약 → 묶음 상세(사진·AI 분석·분류 고치기·상태·답변·여행 정보에 알리기) → 이용자 [내 제보]에 답변, 관광지 상세에 임시 알림

## 8. 작업 계획 (확인 받은 뒤, 이 순서로)
1. `reports_store.py`(읽기·쓰기 한 곳, 상태 이름 맞추기, 가상 데이터 분리) + `/api/reports` 확장(위치·종류·누가·사진 3장·연락처 동의·접수번호·제보 수 제한)
2. `ai_triage.py`(triage·cluster·report) + 규칙 대신 + 서버 검사 + `ai.py` TASKS 등록
3. 관리자 [제보·민원]: 목록·묶음 상세·지도·기간 요약·설정·백업 / 기존 [AI 제안]·임시 알림 연결
4. 이용자 폼·접수 화면·[내 제보]·공개 지도 층, i18n(ko·en), 데모(`build/api.js`) '연결 안 됨'
5. 가상 데이터 18건 + `tests/test_city_reports.py`(가짜 Claude) + 기존 점검 3종
6. 로컬에서 화면 확인(이용자 폼·관리자 목록·지도·보고서) → CHANGELOG·HANDOVER
